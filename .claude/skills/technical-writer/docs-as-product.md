# Skill: Documentation as a Product Deliverable

Load this skill instead of `functional-documentation.md` when the
documentation itself is part of what a customer is buying or receiving
— a template, a packaged product, a freelance deliverable being handed
off — rather than an internal stakeholder-facing description of a
feature change.

## Required experience

A new customer/recipient should be able to:

1. understand what they got
2. install/import it
3. reach the first successful result
4. customize it
5. troubleshoot common issues

## Structure

Overview → Requirements → Quick Start → Setup → Customization →
Reference → Troubleshooting → FAQ → Changelog → License.

Use task-oriented headings ("Change the accent color", not "Theming
architecture"). Avoid documentation that merely mirrors source-code
structure — organize around what the reader is trying to do.
